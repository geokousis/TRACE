The biological question

Where did each stretch of genome come from?

Observed sample

At each SNP we have genotype evidence: GL, PL, GT, or pileup-derived likelihoods.

Reference panels

Each ancestry source provides allele frequencies. Counts are Beta-smoothed to avoid impossible zero/one frequencies.

Genetic map

Physical distance is not enough. TRACE uses cM distance so recombination scale controls how quickly ancestry can change.

TRACE treats ancestry as a path, not independent SNP labels. Neighboring loci should usually agree unless genotype evidence and recombination distance justify a transition.

Biological analogy

The genome is a mosaic, but the tiles are not independent.

Naive SNP-by-SNP calling

  • 1

    Each SNP is assigned ancestry independently.

  • 2

    Noise can produce unrealistic ancestry flickering.

  • 3

    Recombination distance and LD structure are mostly ignored.

vs

TRACE path inference

  • 1

    Each SNP contributes likelihood evidence.

  • 2

    Neighboring SNPs communicate through a smoothness penalty.

  • 3

    Breakpoints are allowed when evidence overcomes recombination resistance.

Biologically, TRACE asks: “What ancestry path could have generated these genotypes with a plausible number and placement of recombination transitions?”

The objective

Energy balances smoothness against fit to genotype evidence.

S(phi) = D * sum_i pseudoHuber(phi[i+1] - phi[i]) / d_cM[i] - tau * sum_i log P(GL_i | phi_i, f_ref_i) + optional priors

The code uses a pseudo-Huber kinetic penalty. It behaves like a quadratic for tiny changes but is less punitive for real ancestry jumps.

Kinetic term

Penalizes rapid ancestry changes. Higher D means smoother ancestry tracts.

Potential term

Rewards ancestry values that make the observed genotype likelihood plausible.

Genetic distance

Transitions across large cM gaps are easier than transitions across tight LD regions.

Small-picture mechanics

At one SNP, TRACE asks how compatible each ancestry mix is with the observed genotype.

Expected allele frequency

p_i = phi_i f_Ai + (1 - phi_i) f_Bi

If phi is near A, p follows A. If phi is near B, p follows B. Intermediate phi gives a mixture.

Diploid genotype probabilities

P(0/0)=(1-p)^2 P(0/1)=2p(1-p) P(1/1)=p^2

This is the Hardy-Weinberg diploid prior implied by local ancestry.

Observed evidence

L_i = GL_0 P(0/0) + GL_1 P(0/1) + GL_2 P(1/1)

GLs let low-quality data remain uncertain instead of forcing hard genotype calls.

Potential energy

V_i = -tau * log(L_i)

Bad ancestry explanations cost more energy; tau controls how strongly we trust the GLs.

Neighbor mechanics

Between two SNPs, TRACE asks how expensive an ancestry change should be.

Recombination-aware smoothing

K_i = D * pseudoHuber(phi[i+1] - phi[i]) / d_cM[i]

Small genetic distances make switches expensive. Large genetic gaps make switches easier or split the problem entirely.

Why pseudo-Huber?

A pure quadratic can over-penalize real breakpoints. Pseudo-Huber keeps tiny fluctuations smooth but allows sharper biological transitions.

smooth for noise forgiving for breakpoints differentiable
The final path is the compromise: explain the genotypes without inventing too many recombination events.

Likelihood model

Diploid genotype likelihoods make the evidence biologically meaningful.

Binary ancestry

p_i = phi_i f_Ai + (1 - phi_i) f_Bi P(G=0) = (1-p)^2 P(G=1) = 2p(1-p) P(G=2) = p^2

TRACE compares those genotype priors to sequencing likelihoods, not just hard calls.

K populations

phi_i = softmax(theta_i) p_i = sum_k phi_ik f_ik

The K-state solver uses K-1 logits plus a baseline column, keeping ancestry fractions on the simplex.

Data preparation

Most biological errors happen before optimization.

panel QC

Smooth frequencies

Count-format panels use Beta smoothing. This avoids impossible likelihoods when a finite reference panel has frequency 0 or 1.

alleles

Harmonize REF/ALT

TRACE matches by position and alleles, handles reverse complements, and avoids unsafe palindromic strand flips.

ploidy

Set chromosome mode

Male X/Y/MT and user-provided haploid contigs use haploid likelihoods instead of diploid HWE priors.

map

Interpolate cM

Genetic maps convert base-pair positions into recombination scale, with extrapolation at edges.

If reference alleles are wrong, strand handling is wrong, or ploidy is wrong, the optimizer can be mathematically correct and biologically wrong.

Chunking and scale

Million-SNP inference is handled as overlapping local problems.

Why chunk?

L-BFGS-B is memory efficient, but huge chromosomes still need bounded working sets and parallel execution.

Why overlap?

Optimizer edges have less neighbor context. Overlap lets TRACE blend central, better-conditioned estimates.

Why split map gaps?

Centromeres and sparse regions should not force ancestry continuity across uninformative distance.

chromosome → cM segments → overlapping chunks → optimize → blend true overlaps → final path

Complexity

Objective and gradient are O(N) per optimizer evaluation. L-BFGS-B avoids materializing a full N by N Hessian.

Optimization loop

Each L-BFGS-B iteration asks two vectorized questions.

1. What is the current action?

  • A

    Compute ancestry-implied allele frequency at every SNP.

  • B

    Compute genotype likelihood under local ancestry.

  • C

    Add pseudo-Huber smoothness across adjacent SNPs.

2. Which direction reduces it?

  • A

    Potential gradient says how genotype evidence pulls phi.

  • B

    Kinetic gradient says how neighbors pull phi back.

  • C

    Analytical Jacobian avoids slow numerical gradients.

The optimizer is generic; the biological intelligence is in the objective and gradient.

Scenario biology

Benchmarks are not just scores; each one tests a biological assumption.

Tract-like admixture

f1_hybrid, ancient_mosaic, centromere_abyss. These ask whether TRACE can recover discrete ancestry blocks generated by recombination. This is the model's natural regime.

Reference mismatch

bottleneck_drift, ghost_introgression. These test whether TRACE invents ancestry when the panel is distorted or missing the true source.

Continuous ancestry

isolation_by_distance. This is not a tract problem. It tests whether the model can represent stable intermediate ancestry without snapping to A/B.

Data degradation

ancient_dna. This tests whether the path can remain stable when genotype likelihoods are low coverage and noisy.

A good local ancestry method should not only be accurate when its assumptions hold; it should fail visibly when its assumptions are violated.

Failure modes

Each weak scenario tells us what the model is missing.

Ghost introgression

A/B-only reference panels cannot represent unsampled ancestry. Add an unknown state with a prior penalty.

Isolation by distance

Truth is clinal and near-intermediate. Add an interior/global ancestry prior to avoid over-polarization.

Ancient DNA

Low coverage and damage distort GLs. Add deamination-aware likelihoods and tune tau.

Recommended next model: S = kinetic(D_i) + tau * GL_potential + lambda_unknown * phi_unknown + lambda_cline * KL(phi || global_ancestry)

Uncertainty

TRACE now reports local K=2 uncertainty, but calibration still matters.

What changed

Binary TSV outputs use the diagonal of the inverse tridiagonal Hessian. This accounts for neighbor coupling exactly in the 1D binary solver.

SE_i = sqrt( diag( H^-1 )_i )

How to read it

Values near 0.5 mean ancestry is effectively unconstrained at that site on the [0,1] scale. That is a warning flag, not a polished confidence interval.

For publication: validate coverage by simulation and report whether 95% intervals contain truth at the expected rate.

Admixture timing

The ACF estimator is useful, but not yet a demographic claim.

What it does

TRACE computes ancestry autocorrelation along cM and fits one- or two-exponential decay. Under ideal pulse admixture, decay rate relates to generations since admixture.

rho(r) ≈ A exp(-g r) + C

What makes it publishable

Run g=5,10,25,50,100 simulations; use 50-100 replicates; report bias, RMSE, and coverage; compare against ALDER, DATES, or fastGLOBETROTTER where possible.

Current self-check passes: true g=25, weighted estimate=28.5. That is a sanity check, not validation.

Roadmap

The clearest path to stronger biological performance.

1. Tune D and tau

Use the grid-search harness to choose scenario-aware defaults and reveal where structure, not tuning, is limiting.

2. Add unknown ancestry

Add a ghost state with a prior penalty so unsampled ancestry becomes visible instead of forced into A/B.

3. Add clinal prior

Use global ancestry or KL regularization for isolation-by-distance and continuous ancestry gradients.

4. Ancient DNA model

Add deamination-aware errors, missingness weighting, and lower tau defaults for low-coverage data.

5. Publishable validation

Multi-seed simulations, baseline tools, confidence intervals, and benchmark tables by scenario and SNP density.

Bottom line: TRACE is already credible as a tract-like local ancestry solver. Its next leap is adding biological modes for ghost ancestry, clines, and degraded DNA.
